# ADR-0006 — LiteLLM как библиотека (без отдельного gateway)

Статус: принято · Дата: 2026-06-02 · Связано: `architecture.md` §3, ADR-0005

## Context

LiteLLM можно использовать двумя способами: как встроенную библиотеку внутри сервиса либо как отдельный gateway-процесс (прокси) с собственным контейнером. Gateway даёт централизованный учёт/роутинг между многими сервисами, но добавляет процесс и сетевой хоп. В Calorithm единственная точка LLM-вызовов и так — модуль `llm`, один токен, одна модель.

## Decision

LiteLLM — **библиотека внутри модуля `llm`**, без отдельного gateway-процесса. Модуль `llm` — единственная точка LLM-вызовов: ключи, выбор модели, таймауты, ретраи, учёт стоимости/латентности, версионирование промптов и обязательный проход через централизованный LLM-лимитер (ADR-0005).

## Consequences

- (+) Меньше движущихся частей и контейнеров; нет лишнего сетевого хопа.
- (+) Лимитер и учёт стоимости естественно живут в том же модуле — единое место истины о темпе/бюджете.
- (−) Нет внешнего готового gateway-дашборда по LLM — компенсируется собственными Prometheus-метриками (ADR-0010).
- Обратимо: при появлении многих сервисов-потребителей LLM можно вынести gateway, сохранив интерфейс модуля `llm`.

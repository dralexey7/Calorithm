# ADR-0018 — Отключаемая авто-сводка и scheduler как триггер синхронной сводки в `api-core`

Статус: принято · Дата: 2026-06-03 · Связано: `architecture.md` §3, §4.3, §6; `contracts.md` §1.5, §3; US-005, US-008, A6; ADR-0009, ADR-0015 · **Amends: ADR-0009**

## Context

ADR-0015 убрал `diary-worker` и `tasks.diary`: сводка снова синхронна и живёт в `api-core`. Нужно зафиксировать (1) как `scheduler` (stateless-триггер 09:00, ADR-0009) запускает теперь **синхронную** генерацию/доставку авто-сводки, и (2) per-user возможность **отключить** авто-сводку — пользователь не всегда хочет утренний отчёт.

## Decision

**1. Per-user флаг `auto_summary_enabled` (bool, default `true`).** Хранится в схеме `users` (модуль `users`). Меняется через `PATCH /v1/users/settings`. Если `false` — авто-сводка пользователю не строится и не шлётся.

**2. `scheduler` триггерит синхронную сводку в `api-core`.** `scheduler` остаётся stateless-триггером 09:00 (ADR-0009): тикает по времени, и для пользователей с локальным 09:00 **дёргает внутренний механизм `api-core`** (HTTP внутри compose-сети — `POST /v1/internal/auto-summary` или эквивалент; конкретный механизм — свобода реализации в рамках «scheduler в БД/LLM не ходит»). `api-core` синхронно: проверяет `auto_summary_enabled`, читает записи за вчера (только `status='confirmed'`, ADR-0016), и если они есть — форматирует и публикует `Result{kind=daily_summary}` в `results.<channel>` для primary-канала (ADR-0009). Если записей нет (A6) или флаг выключен — не шлёт.

`scheduler` сам сводку не строит, в БД и LLM не ходит; всю логику (фильтр по флагу, чтение, формат, дедуп, публикация) исполняет `api-core`. `tasks.diary`/`build_summary`/`diary-worker` не используются (ADR-0015).

**3. Дедупликация авто-сводки.** Сохраняется `summary_dispatch (UNIQUE user_id, local_date)` в схеме `diary` (владелец — `diary`, пишет `api-core`): повторный/перекрывающийся тик `scheduler` или рестарт не шлёт второй раз. `scheduler` к таблице не обращается (строгая развязка ADR-0001) — дедуп делает `api-core` при обработке триггера.

**4. Авто-сводка только в primary-канал** — без изменений (ADR-0009).

## Consequences

- (+) Пользователь управляет, получать ли утренний отчёт; дефолт — включён (не ломает текущее поведение).
- (+) `scheduler` остаётся максимально тупым триггером; вся доменная логика — в единственном владельце БД (`api-core`), без второго писателя.
- (+) Дедуп через `summary_dispatch` переживает повторные тики/рестарты, как и раньше.
- (−) Появляется внутренний (compose-only) эндпоинт `api-core` для триггера авто-сводки — не публичный, доступен только из compose-сети. Приемлемо; альтернатива (scheduler публикует задачу) вернула бы очередь сводок, от которой ADR-0015 ушёл.
- (−) Авто-сводка теперь делит процесс `api-core` с пользовательскими запросами; при росте — вынос orchestrator-части (ADR-0015), обратимо.
- Флаг `auto_summary_enabled` — ревизией Alembic в схеме `users` (ADR-0014).

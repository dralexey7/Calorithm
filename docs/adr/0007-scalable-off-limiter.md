# ADR-0007 — Масштабируемый глобальный лимитер OFF

Статус: принято · Дата: 2026-06-02 · Связано: `architecture.md` §7.1, US-010, G6

## Context

OpenFoodFacts имеет лимиты; превышение → бан (R3). Требование US-010 — соблюдать лимит **на уровне всей системы**, не на процесс. При нескольких воркерах/репликах in-process счётчик не годится: суммарный темп пробьёт лимит. OFF к тому же слабо покрывает свободные описания готовых блюд (R2) → fallback на LLM штатен.

## Decision

**Масштабируемый лимитер OFF** с **общим состоянием в Redis** (token-bucket / sliding-window, атомарно через Lua или `INCR`+TTL). Единственная точка обращения к OFF — модуль `off_client`; обход запрещён. При исчерпании бюджета — **graceful degradation на LLM-оценку** (US-010, R3): запрос не валится, значение по продукту гарантируется (US-004).

## Consequences

- (+) Лимит соблюдается глобально независимо от числа воркеров/реплик — цель G6 (0 инцидентов бана).
- (+) Штатная деградация: исчерпание бюджета OFF не ломает пользовательский путь, а переключает источник на LLM.
- (+) Единая точка — легко наблюдать (метрика остатка бюджета) и менять стратегию.
- (−) Дополнительная зависимость от Redis на пути nutrition (приемлемо: Redis и так в деплое).
- (−) Деградация на LLM увеличивает долю LLM-источника и стоимость — наблюдается метрикой «OFF vs LLM».
